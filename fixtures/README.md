# Test fixtures

> **The `hwp5/*.hwp` and `hwpx/*.hwpx` documents in this directory are not bundled with the
> repository** (excluded by `.gitignore`, local only). Fetch them from the sources below and place
> them at the same paths to enable the render and PDF tests; without them those tests **skip**
> automatically. Only this README and `golden/README.md` are committed.
>
> A skip still reports `ok`, so `scripts/check.sh` counts them on its summary line
> (`skipped-for-missing-fixtures=N (optional=M)`, listed in `target/fixture-skips.log`), and
> `HWP_REQUIRE_FIXTURES=1` turns every such skip into a failure except the optional sets below
> (#275).
>
> **Exception: `samples/` is committed**, containing anonymized samples of the repository owner's own
> documents and fully synthetic public regression packages. Tests depend on these without skipping.

## samples/ (committed)

- `report-tables.hwpx`: the functional test fixture for table editing (adding rows and columns,
  refusing complex tables) and package-preserving replacement (ten tables: three top-level merged,
  six nested simple, and a simple 7x2 "[별표]").
  - Origin: a document written by the repository owner, cleaned up and pseudonymized for publication
    by the owner directly in Hancom Office (Jeju-area university names became 한빛대학교, 미륵대학교,
    다온대 and so on), then committed **byte for byte** as saved. Because these are the bytes Hancom
    wrote, the line layout cache (linesegarray) is consistent with the content, and reprocessing with
    a tool could make Hancom raise a "corrupt or altered" warning, so it is used as-is without
    recompression or rewriting.
  - `[별표 1] 전문가 등급 기준 <개정 2025.08.14.>` is public-regulation-like content and is included
    verbatim (with the owner's approval). The lastsaveby in content.hpf (`yj.lee`) is kept, being the
    same public information as the repository commit author.
  - Update procedure: the owner edits and saves in Hancom → check that no real names remain (zero
    hits) → confirm `hwp validate` passes → commit the replaced file.
- `style-tables-opaque.hwpx`: a fully synthetic byte-stability fixture for `edit --style-tables`
  with a raw-backed `hp:container`; this is not a genuine Hancom export or derived from private bytes.
  - Origin: release `ahwp 1.6.2` generated a new document from this fresh public GFM table:
    `| Field | Value |`, `| --- | --- |`, `| alpha | 1 |`. Its metadata identifies it as an
    `agent-hwp synthetic fixture`, with no real person or institution data.
  - Construction: the writer-generated header, `Contents/content.hpf`, and other package entries
    are retained. A sibling paragraph was appended before `</hs:sec>` using the public container
    pattern in `crates/hwpx/tests/roundtrip_preserve.rs`: container id `77`, size `1000` by `500`,
    and one `hp:subList` paragraph containing `STYLE-TABLES-OPAQUE-SYNTHETIC-MARKER`. Paragraph ids
    are `9000` (outer) and `9001` (inside the container). No `imgBrush` or image payload is present.
  - Regeneration: run `ahwp new --from source.md --strict -o generated.hwpx` with the table above
    and repeated `--set-meta` values `title=Public synthetic opaque-container table`,
    `author=agent-hwp synthetic fixture`, and
    `subject=Fully synthetic parser/writer regression fixture; not a Hancom export`.
    Then append that public XML pattern to `Contents/section0.xml` and repack the original entries
    in order, retaining `mimetype` as the first stored entry. It contains one 2-row, 2-column table
    and a separate raw-backed Generic container; the table is not nested inside that container.
  - Scope: parser/writer preservation and repeated-styling byte stability only. It establishes no
    Hancom layout, native-opening, or rendering ground truth.

## hwp5/

Taken from the integration test fixtures of
[hahnlee/hwp-rs](https://github.com/hahnlee/hwp-rs) (Apache-2.0):

- `hello_world.hwp`, `bookmark.hwp`, `color_fill.hwp`, `outline.hwp`: minimal per-feature files
  (hwp-rs `integration/project/files`)
- `annual_report.hwp`, `work_report.hwp`: samples close to real documents
  (hwp-rs `integration/naver_documents/files`, originally free Naver document templates)

`annual_report.hwp` embeds decorative images from the template (BinData JPG/PNG) and
`work_report.hwp` embeds a small bitmap (117x17 BMP). The body is an empty template with only
placeholders ("OOOOO", "상세 내용을 입력하세요"), containing no real personal or organizational
information. Every fixture was taken from the Apache-2.0 repository above as redistributed (see the
root `NOTICE`).

## Ground-truth sets not currently held

`crates/hwp-render/tests/render.rs` is written against four more documents saved by Hangul, which
the repository owner does not currently hold and whose source is not recorded here. They are
**optional**: without them the tests skip, the skip is counted in `optional=M`, and
`HWP_REQUIRE_FIXTURES=1` does not fail it.

- `hwp5/multicol.hwp`, `hwpx/multicol.hwpx`: a two-column body. Proves page flow across
  columns: a column break must not be taken for a page break (3 pages, not 5), and page 1 draws
  the left and right columns side by side.
- `hwp5/equation.hwp`, `hwpx/equation.hwpx`: a real Hangul equation script (multi-line `#`,
  fractions, sub/superscripts, roots, Greek letters). Proves both formats typeset it (hwp5
  through the eqed parse, HWPX through the `hp:equation` capture) with comparable ink.
