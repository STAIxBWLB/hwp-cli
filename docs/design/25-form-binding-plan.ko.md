# 원본에 결속된 양식 바인딩 계획

**상태: 버전 1 구현.** #411 아래 #418의 계약이며 영문이 정본이다.
복합 `apply_form_bindings` API와 초기 계획 계약은 승인되었다. 이 문서는 설계를 명시하며
릴리스된 CLI·MCP 도구·바이너리에서 사용 가능하다는 뜻은 아니다. 기존 연산과 #358의
스냅샷 규칙은 바뀌지 않는다.

## 목적과 증거 경계

제공된 네이티브 양식의 정확한 개별 위치를 검토한 뒤 각 리터럴 의미 키를 명시적으로
선택한 모든 위치에 연결한다. 기존 발견 패턴, 복제·splice·셀 편집 프리미티브, 편집
트랜잭션의 원자적 writer를 재사용한다. 양식을 재생성하거나 별도 편집기를 만들지 않는다.

이 계약은 구조·의미 편집 예산을 제공한다. 폰트 해석·쪽 나눔·잘림·렌더 품질·한컴 열기와
내보내기는 #419와 [24-original-form-contract.ko.md](24-original-form-contract.ko.md)의
별도 증거다. 재배치 허용은 레이아웃 통과가 아니다. 쪽 나눔·스타일 작업은 #420, 전체
워크플로우는 #421에 속한다.

## 발견 계약

`form-discovery-v1.schema.json`은 `crates/hwp-convert/src/form/binding.rs`의
`FormDiscovery`, `FormOccurrence`와 대응한다. 버전 1은 닫힌 계약이며 null 가능 필드도
모두 직렬화한다. 개별 위치는 최대 20000개, 경로 인덱스는 최대 32개다.

| 필드 | 의미 |
|---|---|
| `id` | `occ-`와 소문자 SHA-256 64자리. 원본 해시·모델 경로·종류·범위·이전 텍스트 다이제스트에 결속되며 권한을 뜻하지 않음 |
| `kind` | `cell_text`, `placeholder`, `inline_value`, `native_field` |
| `paragraph_id`, `section`, `indices`, `model_route` | 지원되는 위치의 기존 체크섬 문단 주소와 정확한 원본 모델 좌표. 미지원 캡션에 편집 가능한 가상 문단 ID를 만들지 않음 |
| `table_id`, `table_index`, `row`, `col` | null 가능한 상위 표 식별자·발견 목록의 표 순번·소유 셀 시작 좌표. 병합에 덮인 좌표는 별도 소유 셀이 아님 |
| `start`, `end` | 반열린 `Paragraph::chars` 인덱스. UTF-8·WCHAR·렌더된 Markdown 오프셋이 아님 |
| `label`, `old_text`, `prior_sha256` | 로컬 검토 근거, 정확한 이전 텍스트와 다이제스트 |
| `bindable`, `cause`, `next_step` | 대상 지원 여부, 유계 거부 원인과 다음 행동. 미지원 위치도 ID와 근거 유지 |

모든 셀 문단은 목록의 대상이며 추론된 레이블-값 소유 관계가 아니다. `label`의 이웃 셀
텍스트는 근거일 뿐이다. 호출자가 개별 위치 ID를 명시적으로 선택하며 반복 레이블과
전체 셀·자리표시자의 겹친 범위를 따로 검토한다. `bindable`은 지원 후보라는 뜻이며 유일성,
자동 소유 관계나 겹침 허가를 뜻하지 않는다. 자리표시자와 본문 인라인 값은 정확한 텍스트
범위를 가진다. 셀의 괄호 빈칸·체크박스·주석형 빈칸은 명시적인 셀 문단 대상으로 검토한다.
발견 단계가 의미 키를 선택하거나 기존 양식 채우기의 정규화·먼저 찾은 값 우선 정책을
몰래 적용하지 않는다.

캡션·원본 보존·혼합 내용 대상은 원인·다음 행동을 가진 목록 전용 항목이다. 네이티브 이름
있는 필드도 `native_field`로 개별 나열하지만 이 계약에서는 연결할 수 없다. `hwp fields`와
기존 이름 기반 필드 작업으로 안내한다. 필드 이름은 근거이며 개별 위치 주소가 아니다.
이 목록이 캡션·원본 컨트롤·네이티브 필드 변경을 지원한다고 약속하지 않는다.

## 원본 식별과 리터럴 키

계획은 소문자 16진수 64자리 `source_sha256`, `structural_sha256`을 담는다. 구조 지문은
값과 구조를 포함한 현재 파싱 IR의 JSON 직렬화를 사용한다. serde가 생략하는 바이너리
본문은 원본 바이트 해시가 결속한다. 지문은 원본 해시를 보완할 뿐 대체하지 않으며 범용
교차 형식 의미 동등성 해시도 아니다.

의미 키는 정규화된 레이블이 아닌 호출자의 리터럴 문자열이며 길이는 1..128자다.
`normalize_form_label`, `form::normalize_label`과 분리한다. 누락·오래된 원본·미지원·겹침·
다중 소유 대상은 발행 전에 거부한다. 전체 계획에서 `(occurrence_id, copy)` 쌍의 소유자는
하나다. #417의 원본→출력 주소는 추출된 원본의 이력이며 이동한 표 인덱스를 추측할 허가가 아니다.

## 승인된 복합 적용과 반복

`apply_form_bindings`는 기존 `edit-ops-v1` 엔진 안의 독립적인 복합 연산이다. 같은 배치의
다른 연산과 함께 쓸 수 없다. 검토된 계획과 리터럴 값을 확인하고 선언된 반복, 명시적 대상
해석, 기존 프리미티브 적용을 수행한 뒤 기존 원자적 트랜잭션으로 한 번 발행한다. 이전 op와
선택자 의미는 바뀌지 않는다. CLI/MCP 전송 경로의 구현·인도 검사는 아직 진행 중이다.

계획 버전 1은 `bindings`, 선택적 `repeats`, 선택적 `constraints`를 담는다. 상한은 바인딩
256개, 바인딩별 대상 1..256개, 반복 16개, 제약 128개다. 각 대상에는 `occurrence_id`,
`max_chars`(1..20000), 명시적인 `allow_reflow` 불리언이 필요하다. `copies` 기본값은 `[0]`,
인덱스는 0..15의 고유 값이며 빈 목록은 허용하지 않는다. 값 맵은 바인딩 키와 정확히
일치하고 최대 256개이며 문자열별 Unicode scalar 값은 최대 20000개다. LF·TAB은 허용하고
CR과 다른 C0 제어 문자는 거부한다. 대상별 `max_chars`도 적용한다.

반복은 원본 `table_id`, 삽입 위치 `after_paragraph_id`, 원본을 포함한 전체 `copies`
1..16개, 그 개수와 정확히 일치하는 호출자 지정 `profile_ids`를 담는다. 프로필 ID는 비어
있지 않은 고유 문자열이며 각각 최대 128자다. 프로필 소속은 명시하며 반복 레이블로
추론하지 않는다. 하나에서 네 개로 만들면 세 번 복제하며 네 개를 추가하는 뜻이 아니다.

반복 원본과 삽입 앵커는 최상위 본문의 표·문단으로 제한한다. 초기 계약에서 중첩 표의
반복은 지원하지 않는다.

기존 `clone_table`과 ID 재매핑으로 먼저 복제한 뒤 다시 목록화하여 원본→복제 위치·표·프로필
맵을 명시적으로 만든다. 계획 대상은 복제 인덱스를 명시하고 0은 원본이다. keep 모드의
미지원 Generic 내용 거부는 유지한다. 미지원 캡션 내용에 대해서는 발견 순번이 기존
편집 표 인덱스와 같다고 가정하지 않는다.

이 복합 재목록화 경계는 #358을 바꾸지 않는다. 기존 배치는 표 변경 op 뒤에 이전 레이블
좌표를 재사용할 수 없다. 복제 후 바인딩은 검증된 맵을 사용하며 산술 인덱스 이동, 중복
텍스트에서 추측한 앵커, 가상의 편집 가능 ID를 사용하지 않는다.

## 정수 제약과 재적용

`equal`은 `left`, `right`의 정수 값을 비교한다. `sum`은 명시한 키 1..256개의 값을 더해
호출자가 제공한 `total`과 비교한다. 참조한 모든 키에 값이 있어야 한다. 문법은 부호 없는
ASCII 숫자와 선택적인 올바른 세 자리 쉼표 묶음이며 상한은 `i64::MAX`다. 예를 들어
`1,000`, `1000`은 같다. 부호·단위·소수·공백·비ASCII 숫자는 거부한다. 덧셈은 오버플로를
검사하며 오버플로·불일치는 발행을 거부한다. 표현식 문자열·암묵적 수식·총계 추론·평가기는
없다. 진단은 의미 키나 값 문자열을 반복하지 않고 규칙 인덱스와 원인만 밝힌다.

수정한 값은 같은 최초 원본 해시와 검토된 대상·복제 구조에 다시 적용할 수 있다. 변경된
값으로 대상을 다시 발견하지 않고 제약과 정확한 미리보기를 다시 계산한다. 매번 최초
원본에서 시작하므로 이전 출력을 또 복제하지 않는다. 이전 출력이나 변경된 원본에는
새 발견·새 원본 결속 계획·재검토가 필요하다. 구조 지문이 같아도 변경된 원본 바이트에
적용할 수 없다.

## 로컬 미리보기·영수증·의미 예산

명시적으로 요청한 로컬 발견·미리보기에는 레이블·정확한 셀·이전/새 텍스트·복제 맵을
담을 수 있다. 공개 로그와 기본 영수증은 해시, 위치·연산 ID, 횟수, 유계 원인·다음 행동
코드만 담는다. 발견 텍스트·의미 값·기존 셀 내용을 담은 과거 경고를 누출하지 않는다.
영수증은 원본·검토된 계획·값·출력·실제 결과를 결속하며 레이아웃·네이티브 호환성을
증명하지 않는다.
영수증에는 `native_warning_count`만 기록하며 writer·미리보기 렌더의 원래 메시지는
명시적인 로컬 preview의 `native_warnings`에만 둔다. 미리보기 폰트 대체는 의미 손실과
다르며 별도 #419의 렌더·폰트 수용 증거가 아니다.

모든 대상에는 검토된 재배치 허용 여부가 필요하다. `max_chars`는 교체 문자열의 Unicode
scalar 개수를 제한한다. `allow_reflow=false`이면 교체 WCHAR 길이가 이전 범위의 WCHAR
길이를 넘을 수 없다. true는 `max_chars` 안에서 이 길이 증가를 허용할 뿐 폰트 축소·그리드
변경·임의 서식 변경·검토하지 않은 문단 생성을 허용하지 않는다. 어느 길이 검사도 쪽 안의
배치·줄바꿈·쪽 수·잘림의 적합성을 증명하지 않는다.

선언된 반복과 검토된 값 교체 밖의 비대상 텍스트·들여쓰기·문단/글자 속성·그리드·병합 범위·
폭·테두리·서명란·자산은 보존한다. 정밀 문단 범위 편집은 기존 splice 로직을 재사용한다.
`set_cell`이 첫 문단·첫 글자 모양으로 셀을 다시 만든다는 사실만으로 혼합 서식·컨트롤이
있는 내용·문단 수의 보존을 증명할 수 없다. 미지원 대상은 더 넓은 재작성 경로를 호출하지
않고 거부한다. #419가 별도 폰트·렌더·앵커·네이티브 열기 수용 증거를 담당한다.

## 수용 fixture와 인도

소유자 작성 P0 생성기와 `expected.json`의 정확한 셀·그리드·자산 역할, 반복 레이블, 병합
서명란, 작성된 프로필 네 개를 재사용한다. 이 원본은 이미 프로필 네 개이므로 실제 반복의
증거가 아니다. 같은 작성 청사진에서 제공 중인 #417 제목 범위 추출을 거쳐 프로필 하나인
보조 원본을 만들고 실제 원본→출력 맵을 유지한다. IR 문단 배열을 수동으로 자르지 않는다.
실제 세 번 복제해 네 개로 만들고 복제 후 매핑을 검증한다.

P0 `FormProjection`, `ExpectedCell`, `expect_cell_values`와 비교기는 production import가
아닌 테스트 오라클이다. 기존의 문단·서식 예산은 유지하며 더 넓은 의도적 변경은 명시적 기대
문서·투영이 필요하다. 양쪽 형식, 수정 배분 일관성, 오래된 원본·모호성의 원자적 거부,
미지원 대상 목록, CLI/MCP 동등성, 전체 저장소 게이트를 검사한다. 비공개 양식·독점 폰트·
명세 추출물에서 fixture를 파생하거나 합성 의미 검사를 한컴 열기·내보내기 증거로 확대하지 않는다.
