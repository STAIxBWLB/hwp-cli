# 원본에 결속된 양식 바인딩 계획 제안

**상태: 제안, 미구현.** #411 아래 #418을 위한 초안이며 영문이 정본이다. 아래의
`ApplyFormBindings`는 제안된 복합 연산으로, 현재 CLI 플래그·편집 op·MCP 도구나 승인된
스키마가 아니다. API와 스키마 승인은 미결이며 #358의 스냅샷 규칙을 포함한 기존 명령의
동작은 바뀌지 않는다.

## 목적과 경계

제공된 네이티브 양식의 채울 수 있는 위치를 개별적으로 발견하고, 사람이 정확한 대상을
검토한 다음 하나의 리터럴 의미 키를 의도한 모든 위치에 연결한다. 기존 발견·표 복제·텍스트
splice·셀 편집·원자적 발행 경로를 재사용하며 양식 재생성이나 별도 편집 엔진을 만들지 않는다.

이 제안은 구조·의미 편집 예산을 다룬다. 폰트 해석, 쪽 나눔, 잘림, 네이티브 렌더 품질이나
한컴 열기·내보내기 호환성을 증명하지 않는다. 이들은 #419와
[24-original-form-contract.ko.md](24-original-form-contract.ko.md)의 별도 증거가 필요하다.
쪽 나눔·스타일 작업은 #420, 전체 사용자 워크플로우는 #421의 범위다.

## 개별 위치 목록

반복 레이블도 거부·모호 후보를 포함해 각각 유지한다. 현재 `scan_form_fields`의 키·횟수
목록은 정확한 대상 목록이 아니다.

| 제안 필드 | 의미 |
|---|---|
| 개별 위치 ID | 원본 해시·모델 경로·종류·원본 범위에 결속된 결정적 ID. 권한이나 다른 원본에 재사용할 ID가 아님 |
| 종류 | 자리표시자, 본문 인라인 값, 오른쪽/아래 값 셀, 괄호 빈칸, 체크박스, 주석형 빈칸. 네이티브 이름 있는 필드는 범위 결정 대기 |
| 대상 | 소유 셀 좌표 또는 정확한 문단·텍스트 범위. 주소가 있는 곳은 기존 v2 ID/`SegmentPath` 사용 |
| 컨테이너 | 표 식별자, 재귀 표 인덱스, 셀 시작 좌표·병합 범위, 상위 모델 경로. 병합 셀에 덮인 좌표를 새 소유 셀로 취급하지 않음 |
| 프로필 식별자 | 호출자가 부여한 논리 식별자와 명시적 소속. 반복 레이블만으로 추론하지 않음 |
| 근거 | 레이블 위치, 패턴·대상 선택 정책, 이전 값의 기대 다이제스트, 사용한 원본 좌표 규약 |
| 해석 상태 | 확정·모호·미지원 상태, 후보 ID, 상한이 있는 원인·다음 행동 코드 |

의미 바인딩 키는 호출자의 리터럴 키다. 서로 다른 기존 매칭 계약을 구현한
`normalize_form_label`, `form::normalize_label`과 분리한다. 어떤 발견 정책이 후보를
제안했는지 근거에 기록하며, 유사 매칭이나 겹침 우선순위를 자동 선택의 허가로 취급하지
않는다. 하나의 위치에 충돌하는 키를 연결할 수 없다.

텍스트 위치는 UTF-8 매치 오프셋, `para.chars` 인덱스, WCHAR 위치를 구분한다. 렌더된
Markdown 범위와도 호환되지 않는다. 기존 텍스트·splice 경로의 정해진 경계에서 변환하고
적용 전에 원본 범위를 확인한다.

표·프로필 ID는 이 원본 안의 개별 위치를 식별하며 네이티브 영구 ID를 뜻하지 않는다.
#417로 추출했다면 원본→출력 주소 맵을 이력으로 유지한다. 이동한 표 인덱스를 추측하지 않는다.

## 원본과 검토의 결속

계획은 정확한 원본 SHA-256과 선택한 표 소속·그리드·병합·폭·지원 의미 서식 투영을 다루는
구조 지문을 담는다. 지문의 필드와 정규화 규칙은 스키마 검토가 필요하다. 지문은 원본 해시를
보완하며 다른 원본 바이트에 적용할 권한을 주지 않는다.

검토에서는 각 키의 위치 ID, 선언된 복제, 대상별 편집 예산을 명시적으로 선택한다.
누락·모호·겹침·오래된 원본·미지원 바인딩은 발행 전에 거부한다. 기존 양식 채우기의
먼저 찾은 값 우선 경고를 이 계획의 모호성 정책으로 바꾸어 쓰지 않는다.

## 제안된 복합 적용

독립적인 `ApplyFormBindings` 제안 연산은 기존 `edit-ops-v1` 실행·발행 경로로 들어간다.
기존 op나 선택자 의미를 대체하지 않는다. 상한이 있는 요청은 검토된 계획, 리터럴 값,
명시적 허용 범위를 참조한다. 정확한 wire 표기·상한·CLI/MCP 형식·스키마 승인은 미결이다.

복합 연산의 제안 순서는 다음과 같다.

- 원본 식별, 구조 지문, 검토된 선택, 상한이 있는 제약 확인
- 기존 `clone_table`과 ID 재매핑으로 선언된 프로필 반복만 수행
- 복제 뒤 다시 목록화하고 이전→새 위치·표·프로필의 명시적 맵 생성
- 검토된 복제 후 대상 집합 해석, 기대 변경 미리보기, 모호성 거부
- 기존 텍스트 splice 또는 셀 편집으로 적용한 뒤 원자적 writer로 한 번 발행하며 기존 거부·보존 보고 유지

프로필 목표 개수는 원본을 포함한다. 원본 하나에서 목표 네 개라면 세 번 복제하며 네 개를
추가하는 뜻이 아니다. 복제 모드와 허용 내용은 명시하며, keep 모드의 미지원 Generic 개체
거부는 계속 유효하다.

복제 후 다시 목록화하는 단계는 제안된 복합 연산 내부의 명시적 경계다. 기존 배치의 #358을
완화하지 않는다. 앞선 op가 표를 복제·이동했다고 이전에 해석한 레이블 좌표가 유효해지는
것이 아니다. 복제 후 대상에는 검토된 매핑 규칙이 필요하며 좌표 계산 추측이나 가상의
편집 가능 ID를 사용하지 않는다.

## 제약과 값 수정

호출자가 제공하는 총계는 닫힌 유계 정수 모델로 검사한다. 동등성 및 명시적으로 나열한
유계 정수 바인딩 키의 합을 호출자가 제공한 정수 총계와 비교한다. 누락·정수가 아닌 값·검사된
산술 오버플로를 거부한다. 표현식 문자열, 스크립트, 함수, 암묵적 수식, 소계 추론이나 일반
평가기는 없다. 정확한 정수 범위·목록 상한은 스키마 승인 대기다. 소계·총계는 호출자가
제공하며 검사 실패는 발행을 거부한다.

검토된 계획은 같은 최초 원본 해시와 같은 대상·복제 구조에 수정한 값을 다시 적용할 수
있다. 새 값으로 제약과 정확한 미리보기를 다시 계산하되 대상 선택과 선언한 예산은 고정한다.
매번 최초 원본에서 시작하므로 이전 결과를 다시 복제하지 않는다. 이전 출력이나 변경된
원본에 적용하려면 다시 목록화하고 새 원본에 결속된 계획과 검토를 거친다. 구조 지문이
같다는 사실만으로 이 경계를 넘을 수 없다.

## 미리보기·영수증·편집 예산

명시적으로 요청한 로컬 미리보기에는 정확한 셀·레이블 근거·이전/새 값·복제 맵을 담을 수
있다. 공개 로그와 기본 영수증에는 해시, 위치·연산 ID, 횟수, 유계 원인·다음 행동 코드만
기록한다. 문서 텍스트·값 문자열·기존 셀 내용을 담은 과거 경고를 내보내지 않는다. 영수증은
원본·검토된 계획·값·출력·실제 적용 결과를 결속하며 해시가 레이아웃이나 네이티브 호환성을
증명하지는 않는다.

모든 대상에는 검토된 재배치 허용 범위와 의미 편집 예산이 필요하다. 허용할 값 교체, 문단 수
변경, 복제 추가, 대상 서식 변경을 선언한다. 명시적 허용 밖의 비대상 셀 텍스트·들여쓰기·
문단/글자 속성·그리드·병합 범위·폭·테두리·서명란·보존 자산은 유지한다. 폰트를 몰래 줄이거나
열 구조·임의 서식 변경을 허용하지 않는다. 검토된 예산을 넘는 긴 값은 대상 ID와 다음 행동을
제시하며 거부한다.

기존 `set_cell`은 첫 문단·첫 글자 모양을 템플릿으로 삼아 셀 문단 목록을 다시 만든다.
따라서 혼합 서식·여러 문단·컨트롤이 있는 대상이 `set_cell`에서 처리된다는 이유만으로
서식 보존을 약속할 수 없다. 정밀 텍스트 편집은 기존 후보·splice 로직을 재사용하며,
미지원 예산은 거부하거나 명시적으로 검토한다. 별도 재작성 구현을 만들지 않는다. 이 예산은
의미 계약이며 텍스트가 쪽 안에 들어간다는 증거가 아니다. 렌더·폰트·앵커 수용 증거는 #419가
별도로 평가해야 한다.

## 재사용과 미결 결정

- `form.rs`: 후보 패턴 의미는 보존하면서 집계된 `FormField`와 별도로 개별 위치 근거 노출. 기존 정규화와 먼저 찾은 값 우선 충돌 검토
- `edit.rs`: 기존 엔진 안에서 `walk_form_cells`, `find_form_cells_by_label`, `set_cell`, splice, `clone_table` 재사용. 필요한 범위에서만 가시성 확장
- CLI 편집 실행: 원본 스냅샷, 주소 사전 검사, 오프셋 규칙, dry-run/영수증, 원자적 writer 재사용. `fill --forms`는 HWPX 전용이므로 양쪽 형식의 실행기가 아님
- 네이티브 이름 있는 필드: 목록 포함 여부 결정 필요. 기존 `list_fields`, `set_field`는 개별 대상 정밀도가 없는 별도 이름 기반 표면
- 캡션과 원본 컨트롤이 많은 대상: 현재 양식/표 walker는 캡션을 제외하며 일부 원본 보존 컨테이너는 안전한 재생성이 불가능함. 발견 시 미지원으로 기록하고, 공유 순회·직렬화 계약 전에는 세그먼트 ID나 변경 지원을 만들어 약속하지 않음
- 구현 전에 복합 연산·스키마, 유계 지문·제약 모델, 복제 후 매핑 규칙, 지원 편집 예산 승인 필요

## 제안된 수용 fixture

소유자 작성 P0 생성기와 `expected.json`의 정확한 셀·그리드·자산 기대값, 반복 레이블, 병합
서명란, 작성된 프로필 네 개를 재사용한다. 이 원본은 이미 프로필 네 개이므로 하나에서
네 개로 복제했다는 증거는 아니다. 같은 작성 청사진에서 프로필 하나인 보조 원본을 만들어
실제 세 번 복제와 복제 후 맵을 검사한다. 두 원본 모두 비공개 양식·독점 폰트·명세 추출물에서
파생하면 안 된다.

P0 `FormProjection`, `ExpectedCell`, `expect_cell_values`와 비교기는 production import가
아닌 테스트 오라클로 재사용한다. 기존 기대값 helper는 문단 수를 보존하고 혼합 서식·컨트롤이
있는 값 교체 예산을 거부한다. 더 넓은 의도적 변경에는 명시적 기대 문서/투영이 필요하다.
양쪽 형식, 오래된 원본·모호성의 원자적 거부, 수정 배분의 일관성, CLI/MCP 동등성을 각각
검증한다. 이 합성 의미 검사 결과는 한컴 열기·내보내기 증거가 아니다.
