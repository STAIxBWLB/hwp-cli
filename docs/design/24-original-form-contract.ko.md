# 원본 서식 보존 계약

이 P0 계약은 [#411](https://github.com/STAIxBWLB/hwp-cli/issues/411)의 하위 작업
[#416](https://github.com/STAIxBWLB/hwp-cli/issues/416)에 해당한다. 제공된 네이티브 서식을
유지하는 작업의 제한된 비교 범위와 소유자가 작성한 합성 fixture를 정의한다. 영어 문서가
정본이다. 투영 비교의 통과는 검사한 필드에 대한 근거이며, 새로운 네이티브 포맷 규칙이나
한컴오피스에서 산출물이 열린다는 증명은 아니다.

## 범위와 제공 경계

P0의 산출물은 결정적 저작 명세, 기대값, 공유 테스트 헬퍼와 부정 자체 점검이다. 범위 추출(#417)은
`ahwp split --from`으로 따로 구현되었고 그 테스트가 이 헬퍼를 정답지로 쓴다. P0는 운영용 바인딩
계획(#418), 원본 서식 인증(#419), 페이지·서식 연산(#420), 전체
CLI/MCP 작업 흐름(#421)은 구현하지 않는다. 실행은 기존 edit, compose, compare, render
연산을 사용한다. 헬퍼의 메모리상 기대 문서는 테스트 정답지이며, 새로운 공개 편집·인증 API가
아니다.

비교 지원 코드는 `crates/hwp-cli/tests/common/`의 `FormProjection`, `ExpectedCell`,
`ContractViolation`, `project_form`, `compare_form_contract`를 사용한다. `AnchorPositions`
수집과 `compare_anchor_positions`는 #410의 앵커 비교 방식을 재사용하면서 렌더 관측과 구조
투영을 분리한다. 정확한 시그니처는 테스트 코드가 정의하며, 이 이름들이 출시된 CLI/MCP
명령을 뜻하지 않는다.

`expect_cell_values`는 기대 투영을 복제해 수정할 뿐 원본 `Document`를 편집하지 않는다. 닫힌
교체 예산은 기존 문단 수를 유지하며 단일 스타일 문단만 허용한다. 문단 삽입이나 혼합 스타일
교체에는 텍스트 허용 범위를 넓히는 대신 명시적인 기대 문서·투영을 제공해야 한다.

문자열 기반 셀 예산은 일반 텍스트, 탭, 줄바꿈을 지원한다. 그 밖의 제어 코드가 있는 셀 값은
projection에 타입이 있는 제어 atom으로 보존하며 명시적인 expected 문서를 요구한다.
이를 평탄화한 문자열로 일치 처리하거나 암묵적으로 교체하지 않는다. 숫자 코드가 같아도
CharCtrl과 InlineCtrl은 서로 다른 atom 종류로 유지한다. ExtCtrl atom은 code, `ctrl_id`,
참조하는 control index를 보존하므로 보이는 텍스트가 같아도 필드·개체 앵커 변경을 숨길 수 없다.
선택적인 마지막 문단 종료문자만 정규화하고, 문단 중간의 문단 나누기 제어문자는 atom으로 유지한다.
네이티브 원본 payload tail은 이 의미 투영의 범위 밖에 남는다.

생성 원본 테스트는 두 HWPX 사본의 전체 투영을 비교한다. 두 포맷은 각각 manifest의 셀 값,
격자 폭·병합 범위, 서식 표식·나누기와 자원 역할을 검사한다. HWP5에는 별도의 전체 투영
기준선과 바이트 동일 네이티브 왕복 검사가 적용된다. 이는 포맷 간 보편적인 서식 동일성을
단언하거나 writer의 구체화 차이를 정규화해 없애는 검사가 아니다.

## 합성 원본 재생성

저장소 루트에서 실행한다.

```sh
python3 tools/generate_original_form_fixture.py target/original-form-fixture
ahwp compose target/original-form-fixture/original-form.spec.json \
  -o target/original-form-fixture/original-form.hwpx
```

표준 라이브러리만 사용하는 생성기는 네 파일을 출력한다.

- `original-form.spec.json`: 부동 표를 사용하는 DocumentSpec 2.0과 그 안의 1.0 문서.
- `inside.png`, `outside.png`: 외부 그림이나 글꼴 없이 결정적으로 인코딩한 서로 다른 원본
  2x2 RGB 체크 이미지.
- `expected.json`: 버전이 있는 출처 정보, 명세·이미지 SHA-256, 서식 표식과 문단 인덱스,
  표 식별자, 셀 좌표·병합 범위·폭과 기대 텍스트 값.

전체 원본에는 앞부분의 무관한 이미지, 신청서, 세 개의 이론·실습 배분이 있는 개발 보고서,
네 개의 프로필 표, 반복 라벨과 병합된 서명 영역이 있다. 보존 대상 이미지는 신청서 표의 셀
안에 있다. 각 서식·프로필에는 페이지 나누기 블록 뒤에 고유한 `FORM_START_*` 제목이 있다.
나누기 블록은 별도 문단으로 컴파일되므로 제목 자체에 나누기 플래그가 있다고 가정하면 안 된다.
manifest 좌표는 구역 설정 문단을 포함한 컴파일 원본 기준이며, 이후 추출본의 주소가 아니다.

모든 스타일의 문단 위·아래 간격은 0이다. 이는 #415의 미해결 간격 단위 보정에 의존하지
않으려는 설정이며, 일반적인 0 간격 규칙이나 페이지 수 규칙을 확정하지 않는다. 생성기는
Noto Sans CJK KR을 요청하지만 글꼴을 포함하거나 실제 해석된 글꼴 식별자를 고정하지 않는다.
명세·자산은 바이트 단위로 재생성할 수 있으며, 네이티브 산출물과 렌더 근거에는 생성에 사용한
제품 HEAD와 글꼴 환경을 추가로 기록해야 한다.

비공개·제3자 원본 서식, 원본에서 유래한 바이너리 fixture, 독점 글꼴, 한컴 명세 파생물은 입력에
사용하지 않는다. 생성된 네이티브 파일은 기존 compose와 writer 경로의 출력이며, HWP 레코드
바이트를 직접 작성하지 않는다. 출력 확장자 변경이나 기존 명령을 통한 변환으로 다른 포맷을
검사할 수 있지만, 그것이 네이티브 열기 근거가 되지는 않는다.

## 비교 계층

| 계층 | 검사 계약 | 근거의 경계 |
|---|---|---|
| 셀 값 | 명시한 표·격자 좌표의 정확한 기대값, 문단 경계와 공백 보존 | 반복 라벨은 고유 주소가 아니며, 전체 평문 일치만으로 올바른 셀 채움을 입증할 수 없음 |
| 격자 | 표·셀 개수, 행·열 좌표, 병합 범위, 폭, 저장된 최소 높이와 작성된 격자 | 누락·추가된 표나 셀은 실패이며, 위치별 `zip`으로 남는 항목을 버리면 안 됨 |
| 의미 서식 | 아래에 정의한 공통 속성을 참조 해소 후 비교 | 팔레트 인덱스와 불투명 직렬화 세부사항은 서식의 정체성이 아님 |
| 자원 | 해석된 payload 해시와 참조 위치, 명시한 보존·제외 역할 | 파일명이나 해석되지 않은 참조만으로 자산 바이트를 입증할 수 없음 |
| 페이지 | 나누기·앵커 제약과 동일 환경의 상대 관측 | CI는 환경 공통 골든 페이지·글리프·픽셀을 단언하지 않음 |
| 글꼴 | 원래 요청과 별도로 기록한 해석 결과·바이트 식별자 | family 이름 일치만으로 실제 글꼴이 고정되지 않음 |
| 네이티브 열기·내보내기 | 정확한 전달 산출물에 대한 사용자 실기 기록 | 구조 유효성, 빈 손실 원장, CLI 렌더만으로 충족되지 않음 |

격자 주소에는 해당 표의 식별자와 셀의 시작 행·열이 포함되며, 병합 점유 범위는 시작 좌표와
별도로 기록한다. `Course`, `Year`, `Signature` 같은 라벨도 보존 대상 값이다. 네 프로필의 각
출현 위치를 개별 식별해야 한다. 추출·복제 이후 원본과 출력 사이의 주소 대응은 후속 작업의
책임이다.

## 의미 서식 투영

각 문서의 header를 따라 참조를 해소한 뒤 숫자 팔레트 ID 대신 값을 비교한다. 공통 부분집합은
문단 정렬·들여쓰기·좌우 여백·위아래 및 줄 간격, 각 문자 run의 요청 글꼴명·크기·굵게·기울임·
글자색, 해석된 테두리·채움 값, 셀 세로 정렬 속성, 표의 의미적 페이지 나누기 정책을 포함한다.
표 정책은 `Table::page_break_policy`로 해석한 `none`, `table`, `cell`을 비교하며, 원시 표 속성의
모든 비트를 비교하는 것은 아니다. 이름 있는 스타일 배정은 `header.styles`를
따라 해소하고 직접 서식이 같더라도 이름·영문 이름의 정체성을 비교한다. 유효하지 않은
`StyleId`는 이름 없는 기본값이 아니라 해소되지 않은 참조다. 이는 제한된 명명 스타일 식별자
검사이며 모든 네이티브 스타일 payload를 비교한다는 뜻은 아니다.

run 경계 정규화는 실제 서식 변화를 보존하면서 중복된 인접 동일 run만 차이로 보지 않아야 한다.
WCHAR 내용 길이에는 문단 내부의 paragraph-break control을 포함하며, 마지막에 선택적으로
붙는 `CharCtrl(PARA_BREAK)` 종결자 하나만 정규화해 제외한다. 내부 나누기 뒤의 서식 run도
계속 투영 대상이다.

일치를 만들기 위해 의미가 다른 필드를 정규화하면 안 된다. 공유 IR이 표현하지 못하는 포맷 간
차이나 writer의 변경은 명시한 한계 또는 좁고 검토된 기대 변경으로 남겨야 한다. 알 수 없는
참조는 위반이며, 헬퍼가 기본 서식으로 조용히 대체하면 안 된다. 탭 정의 인덱스 0도 다른
인덱스와 동일하게 검증한다. 0이라는 이유로 존재하지 않는 탭 정의 참조를 예외 처리하지 않는다.

줄 캐시, instance ID, 컨테이너 메타데이터, 불투명 원본 레코드와 네이티브 필드 tail은 이 의미
부분집합에 포함되지 않는다. 해당 영역에는 적용 가능한 독립 HWP5 바이트 동일성, 원본 보존
writer, typed 보존 원장 게이트가 계속 적용된다. 투영 일치만으로 그 계층을 인증할 수 없다.

## 기대 변경과 자원 선택

기준선 비교는 선언하지 않은 변경을 허용하지 않는다. 의도한 채움은 정확한 `ExpectedCell`
좌표·값으로 지정하거나 해당 연산의 명시적 기대 문서·투영으로 제공한다. 표 반복과 연도 라벨의
의도적 변경은 결과 개수·주소까지 기대값에 반영한다. 텍스트·병합·폭·서식·자원을 전부 무시하는
옵션은 없다. 비대상 셀과 서명 영역은 계속 기준선과 비교한다.

전체 원본 자원 목록에는 두 이미지가 모두 포함된다. 추출 계획은 서식 안 이미지를 보존하고,
무관한 바깥 이미지는 의도적 제외 대상으로 명시해야 한다. P0 fixture·manifest는 역할을
식별할 뿐, 자원을 조용히 제거하거나 자원 closure를 구현하지 않는다. 참조된 자산의 누락은
계획된 제외와 다른 실패다. 변환에서 바뀔 수 있는 HWP/HWPX 컨테이너 이름 대신 해석된
payload 바이트를 해시한다.

작성한 fixture는 보존 이미지의 셀뿐 아니라 표 식별자도 검사한다. manifest 위치의 `table_id`를
작성된 표 목록에서 찾고, 해당 항목의 `table_index`로 투영의 표를 선택한 다음, 이미지 경로가
그 표의 key와 행·열 접두어를 포함하는지 확인한다. payload 해시가 같아도 다른 표의 동일한
행·열로 옮겨졌으면 실패한다. 바깥 이미지는 manifest의 구역·문단 주소로 검사한다. 이는 원본
fixture의 역할 검사이며, 추출 이후 주소를 대응하는 운영 기능이 아니다.

기존의 자기완결 JSON 내보내기 경로는 `convert --to json --embed-bin`이다. payload 바이트가
없는 JSON 덤프는 완전한 이미지 왕복이 아니다. 의미·자원 투영의 통과도 strict 변환을 통과시키기
위해 무관한 불투명 패키지 항목을 버리는 근거가 되지 않는다.

## 앵커·글꼴·네이티브 근거

구조 검사는 명시적 나누기 의도와 렌더 위치를 독립적으로 기록한다. 앵커 수집은 렌더러 segment
map을 통해 서식 표식과 표 조각을 페이지·상자에 대응한다. 하나의 글꼴 환경에서 원본·출력의
대응 관측을 비교하며, 모든 기대 앵커가 있어야 하고 불완전한 map은 거부해야 한다. 두 앵커
집합이 모두 비어 있다는 이유로 일치 처리하면 안 된다. 누락된 텍스트, 반복된 표 머리행, 전체
페이지 수는 본문 셀의 완전한 표식 검사를 대신하지 못한다.

기하를 비교하기 전에 `anchor_positions`는 기본 옵션의 기존 `to_markdown_with_segments_v2`
문서 순회에서 기대 표 ID 집합을 얻는다. 이미지 추출이나 이미지 I/O는 수행하지 않는다.
관측된 `table` 행의 ID 집합은 기대 집합과 정확히 같아야 하므로, 각 기대 표에 최소 한 행의
관측이 있어야 한다. 두 렌더 map에서 같은 표가 모두 누락되어도, 누락되거나 예상하지 않은
표 근거로 거부한다. 이는 제한된 표 존재 검사이며 모든 표 행·연속 조각의 렌더 완료나 한컴과
동일한 페이지 배치를 입증하지 않는다.

CI 비교는 상대 비교다. 두 산출물은 같은 가용 글꼴 환경을 사용하며, 고정 페이지 수나 픽셀
이미지 대신 대응 앵커를 비교한다. 현재 헬퍼는 선택한 본문 문단의 페이지 배정과 표 조각의
페이지·상자 위치를 비교한다. 표 상자 좌표는 유한값이어야 하며 차이는 #410 헬퍼와 동일하게
**0.05pt 미만**이어야 한다. 이는 상대 허용 오차이며 환경 공통 좌표 골든이 아니다. 호스트 자원
부재로 관측할 수 없으면 skip 집계에 누락 근거를 기록하거나 제한된 결과를 반환한다. 필수 자원
엄격 모드는 검사한 것으로 처리하지 않고 실패해야 한다.

`FontIdentity`는 `FontStore` 관측에서 실제 요청 family·굵기, 해석된 family, 글꼴 바이트
SHA-256, face index와 matched/substituted/missing 결과를 기록한다. 반복성 비교는 관측한
식별자의 일치를 검사하며 CI 글꼴을 고정하지 않는다. fallback 관측이 같아도 matched 글꼴이나
네이티브 호환성 판정으로 바꾸지 않는다. CI 글꼴 근거는 관측 결과이며 외부 고정이 없다고
명시한다. 식별자에는 `resolutions_complete`도 포함한다. 수집이 잘린 경우에는 미확인
근거로 거부하며, 양쪽에 수집된 항목과 완전성 플래그가 같아도 통과시키지 않는다.

글꼴 byte hash, face index 또는 해석 결과가 없으면 동일한 font identity가 아니라 미확인 증거다.
필수 테스트는 이를 자원 부족 skip으로 집계하며 strict mode에서는 실패한다.

페이지·픽셀 수용에는 원본·명세·출력과 렌더 해시, 제품 HEAD·버전, 원래 요청한 family,
해석된 글꼴 바이트 SHA-256·face index·matched/substituted/missing 결과를 기록한 외부 근거가
필요하다. 원래 요청은 유지한다. 고정된 바이트나 완전한 글꼴 해석 결과가 없으면 글꼴·페이지
근거를 제한됨으로 보고하며, fallback 출력을 한컴 동등성으로 표현하지 않는다.

별도 사용자 실기 기록에는 네이티브 출력 해시, 한컴 버전·플랫폼, 열기 결과, 내보내기 결과와
내보낸 산출물 식별자를 기록한다. 실제 작업 전까지는 미검증이다. CLI 유효성, 의미 보존, 진단
완전성, 렌더링, 네이티브 열기·내보내기는 서로 다른 결과다. `render-report.complete`는 진단
수집 완전성을 뜻하며 시각적 정확성을 뜻하지 않는다.

## 알려진 범위 한계와 부정 점검

#410의 제한된 합성 결과는 캐시 없는 출처의 CLI 관측이다. 네이티브 HWP5 편집은 새로운 부동
조각 앵커나 planner 페이지 시작 비트를 적용하지 않고 기존 커서 경로를 유지한다. P0는 이
정책을 확대하거나 probe에서 정품 레이아웃 정확성을 추론하지 않는다. 더 넓은 주장을 제한하는
별도 조사 항목은 다음과 같다.

- #415: 문단 간격 단위 보정.
- #422: 빈 본문·셀의 고정 advance와 합성 지표의 차이, 빈 본문 앵커.
- #423: header/footer 본문 경계, 첫 앵커와 이후 다중 줄 분할 규칙의 차이.
- #424: relayout opt-out 이후 정품 부동 구역 네이티브 편집의 근거.
- #425: 정품 근거가 필요한 네이티브 가로·세로 sentinel 여백 해석.
- #426: 버려지는 앵커 prepass 진단과 불완전·기본 앵커.

자체 점검에서는 기대 셀 값, 병합 범위, 서식 시작 관측을 의도적으로 바꾸고 각각 계층별
`ContractViolation`이 발생해야 한다. 부정 점검은 표의 페이지 나누기 정책 변경, 그 밖의 관측은
유효한 렌더 map에서 표 근거 제거, 보존 이미지를 다른 표의 동일한 셀 좌표로 옮기는 경우도
포함한다. 각 경우는 대응하는 제한된 검사에서 실패해야 한다. 격자·서식·자원 검사도 관련
변형을 탐지해야 하며 전체
문서 텍스트 일치 하나에 의존하면 안 된다. 테스트용 손상 사본은 헬퍼의 거부 경계를 검증하는
용도이며 운영용 추출·바인딩 기능이 아니다. 최종 검사 HEAD에 대한 전체 `scripts/check.sh`,
호스팅 CI, fixture skip, 네이티브·oracle 근거는 별도로 보고한다. P0 결과는 모든 네이티브 표의
PDF 지원을 보장하지 않는다.
