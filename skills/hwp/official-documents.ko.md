# hwp-cli로 작성하는 한국 공문서

이 하위 안내서는 `hwp`로 한국 공문서(공문)를 작성하기 위한 독립 완결 참조입니다:
마크다운 계약, 여섯 가지 문서 유형별 레시피, 템플릿 슬롯 표, 한국어 별칭 표, 채우기/검증
워크플로우를 담습니다. 영어판이 원본이며 `official-documents.ko.md`(이 파일)가 완전한
한국어 미러입니다. 이후 단계를 명시한 부분을 제외한 모든 내용은 오늘 배포된 바이너리로
동작합니다.

대상 문서 유형 여섯 가지: 기안문, 보고서, 계획서, 회의록, 공고문, 보도자료.

## 1. 마크다운 계약

본문 항목 기호는 입력한 문자가 아니라 **중첩 리스트 깊이**에서 나옵니다. 평범한 중첩
마크다운 순서 리스트를 작성하면 (모든 깊이에서 `1.`, 단계마다 두 칸 이상 들여쓰기)
엔진이 해당 깊이의 기호를 부여합니다:

| 리스트 깊이 | 법정 기호 | 모든 공문서 프로필이 렌더링하는 것 |
|---|---|---|
| 1 | `1.` | `1.` |
| 2 | `가.` | `가.` |
| 3 | `1)` | `1)` |
| 4 | `가)` | `가)` |
| 5 | `(1)` | `(1)` |
| 6 | `(가)` | `(가)` |
| 7 | `①` (U+2460) | `①` |
| 8 | `㉮` (U+326E) | `㉮` |

검증된 구현 경계:

- 모든 공문서 프로필은 법정 8단계 사다리를 지정합니다. HWPX는 맞는 `CircledHangul` 번호
  정의를 직접 씁니다. HWP5는 같은 가시 사다리에 대해 검증된 safe/direct 인코딩 경로를
  사용합니다. 이는 인코딩 결과이지 별칭이나 원본 문서의 raw-byte 동등성 주장이 아닙니다.
- 리스트 8단계는 성공합니다. 내장 HTML 리스트를 포함해 9단계 이상은 실패-폐쇄적으로
  거절되어 출력 파일을 발행하지 않습니다. 2, 6, 8단계는 한컴 오피스 관찰대로 `하` 다음도
  이어서 셉니다.
- **번호 경로에서 기호를 손으로 입력하지 마세요.** 순서 리스트 안에 입력한 `가.`는
  엔진이 부여한 기호 옆에 렌더링되어 번호가 이중으로 매겨집니다.

□ ○ 사다리는 **리터럴 기호 텍스트**로, 리스트 번호와는 별개 축입니다:

- 문단 시작에 `□ ` (U+25A1)를 입력하면 1단계 블록, `○ ` (U+25CB)를 입력하면 2단계입니다.
  엔진은 글리프를 유지하고 문단을 내어쓰기해 이어지는 줄이 기호 뒤에 정렬되게 합니다 —
  자동 마커를 덧그리지 않습니다. `○`만 사용하세요. `◦`, ASCII `o`, `ㅇ`, `❍` 금지.
- `□ `/`○ ` 줄은 앞뒤에 빈 줄을 두어 독립 문단으로 만드세요. 단일 줄바꿈은 주변 텍스트와
  확실히 분리되지 않습니다.
- `- ` 마크다운 불릿은 깊이 1에서 `-`, 깊이 2 이하에서 `·` (U+00B7)로 렌더링됩니다 —
  `□ → ○ → - → ·` 사다리의 아래 두 단입니다.

제목 번호는 **리터럴**입니다: 제목 텍스트에 `Ⅰ. 1.`을 직접 입력하세요 (`Ⅰ`은 U+2160
전각 로마자 — ASCII `I.` 금지). 제목에는 자동 번호가 없습니다.

**항목이 하나뿐이면 일반 문단**입니다: 리스트에 항목이 정확히 하나뿐일 때는 기호 없는
문단으로 작성하세요.

## 2. 문서 유형별 레시피

여섯 유형 모두 `templates/` 아래의 같은 마크다운 골격을 공유합니다(이 파일 옆에 납출됨).
이 골격에 이르는 경로는 둘입니다: `hwp new --template <슬러그-또는-별칭> -o out.hwpx`는
골격을 바로 불러오고(전체 별칭 표는 §4), `hwp new --from <골격> --preset <프리셋>` 다음
`hwp fill`은 슬롯을 하나씩 채웁니다. 아래 레시피는 문서 유형별 참고사항이 필요하므로
`--from` + `hwp fill` 경로를 씁니다. 기본값으로 충분하면 `--template`이 지름길입니다.

| 문서 유형 | 오늘의 프리셋 | 템플릿 골격 | 비고 |
|---|---|---|---|
| 기안문 | `official` (맑은 고딕 12pt/160%; `gian` 호환 별칭 — 계속 동작하며 한 번의 지원 중단 안내 출력) | `gian-internal.md` (내부결재), `gian-external.md` (대외시행) | `gongmun-basic.md`는 순수 대외 공문 기본형 (접수번호/접수일자 없음) |
| 보고서 | `report` (HCR 바탕 15pt/160%) | `report.md` | 머리말/꼬리말 15 mm, `- N -` 쪽 번호; 배경 → 내용 → 계획 → 행정사항 골격 |
| 계획서 | `plan` (HCR 바탕 15pt/160%) | `plan.md` | 머리말/꼬리말 15 mm, `- N -` 쪽 번호; 9개 절 사업계획서 골격 |
| 회의록 | `minutes` (HCR 바탕 14pt/130%) | `minutes.md` | 머리말/꼬리말 여백과 쪽 번호 없음; 공공기록물 관리에 관한 법률 시행령 제18조의 9가지 법정 요소 (D-19) |
| 공고문 | `notice` (맑은 고딕 15pt/160%) | `notice.md` | 머리말/꼬리말 10 mm, `- N -` 쪽 번호; 공고번호 `제2025-282호` 형식 |
| 보도자료 | `press` (HCR 바탕 14pt/160%) | `press.md` | 머리말/꼬리말 10 mm, `- N -` 쪽 번호; 보도시점/배포일 슬롯과 역피라미드 본문 |

프로필은 문서 유형마다 하나씩만 있습니다. 개조식은 보고서·계획서와 내부결재 문서의 본문에서
쓰는 명사형 종결 방식, 곧 문체이므로(`references/korean-official-format.ko.md` §6 어투)
프로필을 선택하지 않습니다. 프로필은 문서 유형으로 고르고 문체는 본문에서 적용하십시오.
여섯 프로필 모두 시작 여백은 위/아래/왼쪽/오른쪽 20/10/20/20 mm입니다. 변별 여백은
`--margin-top`, `--margin-bottom`, `--margin-left`, `--margin-right`로만 명시합니다. 표준
이름은 `official`, `report`, `plan`, `notice`, `minutes`, `press`이며, `gian`, `gongmun`과
문서화된 한국어 이름은 하나의 표준 프로필로 정규화됩니다. `gian` 별칭은 계속 동작하지만
한 번의 지원 중단 안내를 출력합니다.

모든 레시피가 공유하는 관례:

- **`끝.` 종결.** 공문서는 본문 마지막 항목 뒤에 `끝.`으로 닫습니다(붙임이 있으면
  `붙임  … 1부.` 목록 뒤에). 붙임이 하나면 항목 번호를 붙이지 않고, 둘 이상이면 `1.`, `2.`로
  번호를 매깁니다. 규정 참고 문서 §6을 따릅니다.
- **`--doc-foot`으로 만드는 발신명의.** 가운데 정렬 22pt 볼드 발신명의 줄
  (예: `예시대학교총장`)은 `hwp new`가 직접 만드는 네이티브 결문 프레임입니다 — HTML
  조각을 이어 붙일 필요가 없습니다. 생성 시점에 반복 가능한 `key=value` 프레임 인자로
  넘기세요:

  ```bash
  hwp new --from templates/gian-external.md --preset official \
    --doc-foot "발신명의=예시대학교총장" -o draft.hwpx
  ```

  `--doc-foot`은 기안자/검토자/결재자/협조자/시행번호/시행일자/접수번호/접수일자/주소/
  홈페이지/전화/팩스/이메일/공개구분/수신자도 같은 방식으로 담습니다(키마다 플래그 반복).
  수신자는 두문이 `수신자 참조`인 다수 수신 문서의 수신처 목록이며, 지정할 때에만 결문
  마지막 줄로 나오는 유일한 조건부 행입니다.
  `--doc-head`는 기관명/수신/경유를 같은 방식으로 담습니다. `--notice-head`/
  `--notice-foot`/`--press-head`는 공고문/보도자료에 대응하는 프레임입니다. 모든
  프레임은 표이며 문서에 바로 연결됩니다 — 이어 붙일 것도, HTML 블록 정렬 우회도
  필요 없습니다.
- **관인(직인)은 찍지 않습니다.** 전자결재 시스템(온나라/K-Office)이 발송 시 관인을
  삽입하므로 생성하려 하지 마세요.

## 3. 슬롯 표

템플릿별 슬롯 목록입니다. `hwp new --template <슬러그>` 산출물에 `hwp slots`를 실행한
결과를 그대로 옮겼으므로 다시 유도하지 마세요. 슬롯은 본문 마크다운 아니면 템플릿이
갖춘 네이티브 프레임 안에 있는데, `hwp slots`와 `hwp fill`은 양쪽 모두에 닿기 때문에
아래 목록이 채울 수 있는 자리의 전부입니다.

**템플릿에 없는 슬롯은 오류입니다.** `hwp fill`은 실패-폐쇄로
동작해 `--allow-partial` 없이는 아무것도 게시하지 않으므로, 공유 `--set` 목록을 여러
템플릿에 재사용하려면 `--allow-partial`이 필요합니다. 실패-폐쇄는 의도한 설계입니다.
오타 난 슬롯 이름이 조용히 무시되면 빈칸이 그대로 발송되기 때문입니다.

| 템플릿 | 슬롯 |
|---|---|
| `gian-internal.md` | `{{기관명}}` `{{제목}}` `{{본문}}` `{{붙임}}` `{{발신명의}}` `{{기안자}}` `{{기안자직위}}` `{{협조자}}` `{{시행번호}}` `{{시행일자}}` |
| `gian-external.md` | `{{기관명}}` `{{수신}}` `{{경유}}` `{{제목}}` `{{본문}}` `{{붙임}}` `{{발신명의}}` `{{기안자}}` `{{검토자}}` `{{결재자}}` `{{협조자}}` `{{시행번호}}` `{{시행일자}}` `{{접수번호}}` `{{접수일자}}` `{{주소}}` `{{홈페이지}}` `{{전화}}` `{{팩스}}` `{{이메일}}` `{{공개구분}}` |
| `gongmun-basic.md` | 다수 수신 양식입니다. `gian-external.md`와 같되 `{{수신}}`이 없고(두문은 고정 문구 `수신자 참조`), 결문에 `{{수신자}}` 목록이 붙습니다 |
| `report.md` | `{{제목}}` `{{작성자}}` `{{작성부서}}` `{{작성일자}}` `{{배경1}}` `{{배경2}}` `{{내용1}}` `{{내용2}}` `{{내용3}}` `{{계획1}}` `{{계획2}}` `{{행정사항}}` `{{붙임}}` |
| `plan.md` | `{{사업명}}` `{{주관기관}}` `{{책임자}}` `{{사업기간}}` `{{총사업비}}` `{{참여기관}}` `{{배경1}}` `{{배경2}}` `{{필요성1}}` `{{필요성2}}` `{{최종목표}}` `{{연차목표}}` `{{추진전략}}` `{{세부과제1}}` `{{세부과제2}}` `{{세부과제3}}` `{{추진일정}}` `{{예산내역}}` `{{정량효과}}` `{{정성효과}}` `{{성과지표}}` `{{붙임1}}` `{{붙임2}}` |
| `minutes.md` | 9가지 법정 요소: `{{회의명}}` `{{작성자}}` `{{주관}}` `{{일시}}` `{{장소}}` `{{참석자}}` `{{진행순서}}` `{{안건1}}` `{{안건2}}` `{{논의1}}` `{{논의2}}` `{{결정1}}` `{{결정2}}` `{{표결내용}}` |
| `notice.md` | `{{기관명}}` `{{공고번호}}` `{{제목}}` `{{본문}}` `{{공고일자}}` `{{발신명의}}` |
| `press.md` | `{{기관명}}` `{{보도시점}}` `{{배포일}}` `{{담당부서}}` `{{담당자}}` `{{연락처}}` `{{제목}}` `{{본문}}` `{{붙임}}` |

슬롯을 채울 수 있게 유지하는 작성 규칙:

- **`{{본문}}`은 자기 문단에 단독으로 둡니다.** 부분 이어 붙이기
  (`--set "본문=@body.md"`)는 앵커 문단이 정확히 `{{본문}}`만 담고 있을 때만 블록
  교체가 성립합니다.
- **슬롯은 서식 없는 단일 런 일반 텍스트입니다.** 슬롯을 볼드/이탤릭 범위 안이나 줄
  바꿈에 걸쳐 두지 마세요. `hwp fill`은 `{{name}}`을 raw-XML 문자열 치환으로 찾으므로
  여러 텍스트 런에 나뉜 슬롯은 일치하지 않습니다. 증상: `hwp slots`에는 이름이
  보이는데 `fill --set name=…`이 치환 0건을 보고합니다.

## 4. 한국어 별칭 표

템플릿 파일은 영어 슬러그를 쓰고, `hwp new --template`은 슬러그와 아래 한국어 별칭을
모두 받아들입니다 (D-11). 예를 들면 `hwp new --template 기안문-내부결재 -o draft.hwpx`
또는 `hwp new --template gian-internal -o draft.hwpx`처럼 사용합니다.

템플릿은 세 가지를 함께 담고 있습니다. 본문 마크다운, 그 템플릿이 전제하는 정본 프로필,
그리고 자기 `{{슬롯}}` 토큰을 기본값으로 갖는 네이티브 두문·결문 프레임입니다. 따라서 한
줄짜리 기본 형태만으로도 모든 자리를 채울 수 있는 프레임 문서가 나오며, `--preset`이나
프레임 플래그를 따로 붙이지 않아도 됩니다.

`--template`과 `--from`은 둘 다 문서 본문을 지정하므로 함께 쓸 수 없습니다. 반면 `--preset`과
프레임 플래그는 템플릿 기본값을 **덮어쓰는** 인자이므로 함께 쓸 수 있습니다.
`--doc-head "기관명=예시대학교"`를 넘기면 그 칸의 `{{기관명}}` 하나만 바뀌고, 나머지 칸은
슬롯을 그대로 유지합니다.

| 한국어 별칭 | 템플릿 슬러그 |
|---|---|
| 기안문-내부결재 | `gian-internal` |
| 기안문-대외시행 | `gian-external` |
| 공문서-기본 | `gongmun-basic` |
| 보고서 | `report` |
| 사업계획서 | `plan` |
| 회의록 | `minutes` |
| 공고문 | `notice` |
| 보도자료 | `press` |

## 5. 채우기와 검증 워크플로우

정석 레시피 — 생성, 확인, 채우기, 검증 — 독립 완결 (다른 안내서 불필요):

```bash
# 1. 템플릿 골격으로 문서 생성
hwp new --from templates/gian-internal.md --preset official -o draft.hwpx

# 2. 문서가 실제로 담고 있는 슬롯 나열
hwp slots draft.hwpx

# 3. 일반 값 채우기와 본문 부분 이어 붙이기
hwp fill draft.hwpx -o out.hwpx \
  --set "기관명=예시대학교" \
  --set "제목=AI 교육센터 운영계획(안)" \
  --set "본문=@body.md" \
  --set "붙임=운영계획 상세(안) 1부" \
  --set "발신명의=AI학과장"

# 4. 파일을 넘기기 전에 검증 (종료 코드 0 필수)
hwp validate out.hwpx

# 선택: 레이아웃을 눈으로 확인하려면 페이지 렌더링 (CJK 폰트 필요)
hwp render out.hwpx -o page1.png --pages 1 --font-dir fonts/
```

`body.md`는 §1 계약을 따르는 마크다운입니다 (필요하면 HTML 표 블록 포함). 값 안의
리터럴 `@`는 `@@`로 이스케이프합니다. JSON 파일 하나로 일괄 채우려면
`hwp fill --data data.json` (`"parts": {...}`는 이어 붙이기, `"tables": [...]`는 행
채우기). 변경은 실패-폐쇄적임을 기억하세요 — `DROP:` 경고는 아무것도 발행되지 않음을
뜻하고, 일치하지 않는 슬롯은 `--allow-partial`이 없으면 명령 전체를 실패시킵니다.

정직한 공백 하나: fill은 raw-XML 문자열 치환으로 슬롯을 찾으므로, 여러 텍스트 런에
나뉜 `{{slot}}`은 오늘 치환되지 않습니다 (런 가로지르기 채우기는 EDIT-01 공백으로,
2.5 단계 예정). `hwp new --from`으로 만든 템플릿은 각 슬롯을 하나의 런 안에 유지하므로
위 레시피에는 영향이 없습니다.

## 6. MCP

위의 모든 레시피는 `hwp`가 MCP stdio 서버로 실행될 때 MCP 도구와 일대일로 대응됩니다:
`hwp new` → `hwp_new`, `hwp fill` → `hwp_fill`, `hwp render` → `hwp_render`,
`hwp validate` → `hwp_validate`, 그리고 `hwp lint` → `hwp_lint`. 서버는 항상 최소
하나의 `--root`를 지정해 시작해 도구가 샌드박스 작업 공간만 접근하게 하세요. 도구
상세, 샌드박스 의미, 클라이언트 설정은 SKILL.md의 MCP 절에 있습니다.

### 생성 전 린트

`hwp_lint`는 마크다운 파일 `path` 하나만 받고(인라인 텍스트 없음) 서버의 `--root`
샌드박스를 따릅니다. 반환값은 권고성 hwp-lint-report-v1 findings JSON — finding마다
`rule_id`/`severity`/`line`/`col`/`message`, 원문 발췌 없음 — 입니다. CLI 쌍은
`hwp lint <file.md> [--profile gongmun|report] [--json] [--strict]`입니다.

`hwp new --from` 전에 마크다운 골격을 린트하세요. 오류 심각도 구조 finding
(`struct-item-mark`, `struct-roman-heading`)을 먼저 고치세요 — `--strict`에서는 이들이
명령을 실패시킵니다. 표기법 경고는 수동으로 적용하는 권고로 다루세요. 린트는 파일을
다시 쓰지 않습니다.

## 7. 한컴 오피스 최종 확인

자체 검증 (`hwp validate`, `hwp render`)은 회귀를 잡아내지만, 최종 판정은 **한컴
오피스가 파일을 여는가** — 손상, 변조, 복구 대화 상자 없이 — 그리고 보여주는 내용이
의도와 일치하는가입니다. 문서가 도구 고리를 벗어날 때는 출력을 한컴 오피스에서 열어
확인한 뒤 전달하세요.
