# hwp-cli로 작성하는 한국 공문서

이 하위 안내서는 `hwp`로 한국 공문서(공문)를 작성하기 위한 독립 완결 참조입니다:
마크다운 계약, 여섯 가지 문서 유형별 레시피, 템플릿 슬롯 표, 한국어 별칭 표, 채우기/검증
워크플로우를 담습니다. 영어판이 원본이며 `official-documents.ko.md`(이 파일)가 완전한
한국어 미러입니다. 이후 단계를 명시한 부분을 제외한 모든 내용은 오늘 배포된 바이너리로
동작합니다.

대상 문서 유형 여섯 가지: 기안문, 보고서, 계획서, 회의록, 공고문, 보도자료.

## 1. 마크다운 계약

본문 항목 기호는 입력한 문자가 아니라 **중첩 리스트 깊이**에서 나옵니다. 평범한 중첩
마크다운 순서 리스트를 작성하면 (모든 깊이에서 `1.`, 단계마다 두 칸 이상 들여쓰기)
엔진이 해당 깊이의 기호를 부여합니다:

| 리스트 깊이 | 법정 기호 | 오늘 gian/report 프리셋이 렌더링하는 것 |
|---|---|---|
| 1 | `1.` | `1.` |
| 2 | `가.` | `가.` |
| 3 | `1)` | `1)` |
| 4 | `가)` | `가)` |
| 5 | `(1)` | 1단계 형식 반복 — 법정 기호는 2.2 단계 (GONG-01) 부터 |
| 6 | `(가)` | 2단계 형식 반복 — 2.2 단계 (GONG-01) 부터 |
| 7 | `①` (U+2460) | 3단계 형식 반복 — 2.2 단계 (GONG-01) 부터 |
| 8 | `㉮` (U+326E) | 4단계 형식 반복 — 2.2 단계 (GONG-01) 부터 |

엔진 소스와 대조해 확인한 정직한 한계:

- 프리셋 번호 주기는 4단계입니다 (`from_markdown.rs`: `1.` → `가.` → `1)` → `가)`,
  5단계부터 반복). 법정 `(1)` `(가)` `①` `㉮` 기호(깊이 5-8)는 2.2 단계에서 도입됩니다.
  hwpx 라이터는 수준별 `numFormat`을 실제로 방출하므로 번호 정의는 왕복 보존이 됩니다 —
  위의 반복은 오늘 프리셋이 5-8단계에 어떤 형식을 부여하는가에 대한 이야기일 뿐입니다.
- 리스트 깊이는 오늘 최대 7단계입니다. 더 깊은 중첩은 7단계로 합쳐집니다.
- **번호 경로에서 기호를 손으로 입력하지 마세요.** 순서 리스트 안에 입력한 `가.`는
  엔진이 부여한 기호 옆에 렌더링되어 번호가 이중으로 매겨집니다.

□ ○ 사다리는 **리터럴 기호 텍스트**로, 리스트 번호와는 별개 축입니다:

- 문단 시작에 `□ ` (U+25A1)를 입력하면 1단계 블록, `○ ` (U+25CB)를 입력하면 2단계입니다.
  엔진은 글리프를 유지하고 문단을 내어쓰기해 이어지는 줄이 기호 뒤에 정렬되게 합니다 —
  자동 마커를 덧그리지 않습니다. `○`만 사용하세요. `◦`, ASCII `o`, `ㅇ`, `❍` 금지.
- `□ `/`○ ` 줄은 앞뒤에 빈 줄을 두어 독립 문단으로 만드세요. 단일 줄바꿈은 주변 텍스트와
  확실히 분리되지 않습니다.
- `- ` 마크다운 불릿은 깊이 1에서 `-`, 깊이 2 이하에서 `·` (U+00B7)로 렌더링됩니다 —
  `□ → ○ → - → ·` 사다리의 아래 두 단입니다.

제목 번호는 **리터럴**입니다: 제목 텍스트에 `Ⅰ. 1.`을 직접 입력하세요 (`Ⅰ`은 U+2160
전각 로마자 — ASCII `I.` 금지). 제목에는 자동 번호가 없습니다.

**항목이 하나뿐이면 일반 문단**입니다: 리스트에 항목이 정확히 하나뿐일 때는 기호 없는
문단으로 작성하세요.

## 2. 문서 유형별 레시피

여섯 유형 모두 오늘은 같은 방식으로 작성합니다: `templates/` 아래의 마크다운 골격
(이 파일 옆에 납출됨), `hwp new --from <골격> --preset <프리셋>`, 그 다음 `hwp fill`.
`hwp new --template <별칭>` 지름길은 2.4 단계에서 추가됩니다. 아래 레시피는 현재
경로입니다.

| 문서 유형 | 오늘의 프리셋 | 템플릿 골격 | 비고 |
|---|---|---|---|
| 기안문 | `gian` (맑은 고딕 11.5pt 본문) | `gian-internal.md` (내부결재), `gian-external.md` (대외시행) | `gongmun-basic.md`는 순수 대외 공문 기본형 (접수번호/접수일자 없음) |
| 보고서 | `report` (명조 계열 15pt 본문) | `report.md` | 배경 → 내용 → 계획 → 행정사항 골격 |
| 계획서 | `report` | `plan.md` | 9개 절 사업계획서 골격 |
| 회의록 | `report` | `minutes.md` | 공공기록물 관리에 관한 법률 시행령 제18조의 9가지 법정 요소로 재구성 (D-19) |
| 공고문 | `gian` | `notice.md` | 공고번호는 `제2025-282호` (연도표시 일련번호) 형식 |
| 보도자료 | `report` | `press.md` | 보도시점/배포일 슬롯; 역피라미드 본문 (리드문 육하원칙) |

모든 레시피가 공유하는 관례:

- **`끝.` 종결.** 공문서는 본문 마지막 항목 뒤에 `끝.`으로 닫습니다 (붙임이 있으면
  `붙임  1. … 1부.` 목록 뒤에).
- **2.4 단계까지의 발신명의.** 아직 프레임/머리말 장치가 없으므로, 가울데 정렬 22pt
  볼드 발신명의 줄 (예: `예시대학교총장`)은 블록 수준 정렬 계약 (설계 문서 18 §8)을 쓰는
  HTML 조각 부분 파일을 이어 붙여 만듭니다. `hwp fill --set "발신명의=@sender.html"`에
  넘길 부분 파일에 다음을 넣거나 본문 부분에 이어 붙이세요:

  ```html
  <style>
  .cs0 { font-size: 22pt; }
  .ps0 { text-align: center; }
  </style>
  <p class="ps0"><span class="cs0"><strong>예시대학교총장</strong></span></p>
  ```

  조각은 선행 `<style>` 요소를 담고, 임포트는 `.csN`/`.psN` 규칙만 읽으며, 클래스 번호는
  생산자 로컬입니다 (소비자는 이름이 아니라 속성 값으로 모양을 재구성). `.psN`의
  `text-align`은 문단 정렬을 설정하고, 볼드 같은 표시는 클래스가 아니라 태그
  (`<strong>`)에서 옵니다. 이 레시피는 이 하위 안내서와 부분 파일에만 존재합니다 —
  SKILL.md에는 절대 넣지 않습니다.
- **관인(직인)은 찍지 않습니다.** 전자결재 시스템(온나라/K-Office)이 발송 시 관인을
  삽입하므로 생성하려 하지 마세요.

## 3. 슬롯 표

템플릿 골격별 슬롯 목록 (옛 `.hwpx` 템플릿에 `hwp slots`를 실행한 결과를 그대로 —
다시 유도하지 마세요). **템플릿에 없는 슬롯은 무시되므로** 공유 `--set` 목록을 여러
템플릿에 재사용할 수 있습니다.

| 템플릿 | 슬롯 |
|---|---|
| `gian-internal.md` | `{{기관명}}` `{{제목}}` `{{본문}}` `{{붙임}}` `{{발신명의}}` `{{기안자}}` `{{기안자직위}}` `{{협조자}}` `{{시행번호}}` `{{시행일자}}` |
| `gian-external.md` | `{{기관명}}` `{{수신}}` `{{경유}}` `{{제목}}` `{{본문}}` `{{붙임}}` `{{발신명의}}` `{{기안자}}` `{{검토자}}` `{{결재자}}` `{{시행번호}}` `{{시행일자}}` `{{접수번호}}` `{{접수일자}}` `{{주소}}` `{{홈페이지}}` `{{전화}}` `{{팩스}}` `{{이메일}}` `{{공개구분}}` |
| `gongmun-basic.md` | `gian-external.md`와 동일하되 `{{접수번호}}` `{{접수일자}}` 제외 |
| `report.md` | `{{제목}}` `{{작성자}}` `{{작성부서}}` `{{작성일자}}` `{{배경1}}` `{{배경2}}` `{{내용1}}` `{{내용2}}` `{{내용3}}` `{{계획1}}` `{{계획2}}` `{{행정사항}}` `{{붙임}}` |
| `plan.md` | `{{사업명}}` `{{주관기관}}` `{{책임자}}` `{{사업기간}}` `{{총사업비}}` `{{참여기관}}` `{{배경1}}` `{{배경2}}` `{{필요성1}}` `{{필요성2}}` `{{최종목표}}` `{{연차목표}}` `{{추진전략}}` `{{세부과제1}}` `{{세부과제2}}` `{{세부과제3}}` `{{추진일정}}` `{{예산내역}}` `{{정량효과}}` `{{정성효과}}` `{{성과지표}}` `{{붙임1}}` `{{붙임2}}` |
| `minutes.md` | 9가지 법정 요소: 회의 명칭 / 개최기관 / 일시·장소 / 참석자·배석자 명단 / 진행 순서 / 상정 안건 / 발언 요지 / 결정 사항 / 표결 내용 |
| `notice.md` | `{{공고번호}}` `{{공고일자}}` 및 사용하는 공유 슬롯 (`{{제목}}` `{{본문}}` …) |
| `press.md` | `{{보도시점}}` `{{배포일}}` `{{담당부서}}` `{{담당자}}` `{{연락처}}` 및 사용하는 공유 슬롯 |

슬롯을 채울 수 있게 유지하는 작성 규칙:

- **`{{본문}}`은 자기 문단에 단독으로 둡니다.** 부분 이어 붙이기
  (`--set "본문=@body.md"`)는 앵커 문단이 정확히 `{{본문}}`만 담고 있을 때만 블록
  교체가 성립합니다.
- **슬롯은 서식 없는 단일 런 일반 텍스트입니다.** 슬롯을 볼드/이탤릭 범위 안이나 줄
  바꿈에 걸쳐 두지 마세요. `hwp fill`은 `{{name}}`을 raw-XML 문자열 치환으로 찾으므로
  여러 텍스트 런에 나뉜 슬롯은 일치하지 않습니다. 증상: `hwp slots`에는 이름이
  보이는데 `fill --set name=…`이 치환 0건을 보고합니다.

## 5. 채우기와 검증 워크플로우

정석 레시피 — 생성, 확인, 채우기, 검증 — 독립 완결 (다른 안내서 불필요):

```bash
# 1. 템플릿 골격으로 문서 생성
hwp new --from templates/gian-internal.md --preset gian -o draft.hwpx

# 2. 문서가 실제로 담고 있는 슬롯 나열
hwp slots draft.hwpx

# 3. 일반 값 채우기와 본문 부분 이어 붙이기
hwp fill draft.hwpx -o out.hwpx \
  --set "기관명=예시대학교" \
  --set "제목=AI 교육센터 운영계획(안)" \
  --set "본문=@body.md" \
  --set "붙임=운영계획 상세(안) 1부" \
  --set "발신명의=AI학과장"

# 4. 파일을 넘기기 전에 검증 (종료 코드 0 필수)
hwp validate out.hwpx

# 선택: 레이아웃을 눈으로 확인하려면 페이지 렌더링 (CJK 폰트 필요)
hwp render out.hwpx -o page1.png --pages 1 --font-dir fonts/
```

`body.md`는 §1 계약을 따르는 마크다운입니다 (필요하면 HTML 표 블록 포함). 값 안의
리터럴 `@`는 `@@`로 이스케이프합니다. JSON 파일 하나로 일괄 채우려면
`hwp fill --data data.json` (`"parts": {...}`는 이어 붙이기, `"tables": [...]`는 행
채우기). 변경은 실패-폐쇄적임을 기억하세요 — `DROP:` 경고는 아무것도 발행되지 않음을
뜻하고, 일치하지 않는 슬롯은 `--allow-partial`이 없으면 명령 전체를 실패시킵니다.

정직한 공백 하나: fill은 raw-XML 문자열 치환으로 슬롯을 찾으므로, 여러 텍스트 런에
나뉜 `{{slot}}`은 오늘 치환되지 않습니다 (런 가로지르기 채우기는 EDIT-01 공백으로,
2.5 단계 예정). `hwp new --from`으로 만든 템플릿은 각 슬롯을 하나의 런 안에 유지하므로
위 레시피에는 영향이 없습니다.

## 6. MCP

위의 모든 레시피는 `hwp`가 MCP stdio 서버로 실행될 때 MCP 도구와 일대일로 대응됩니다:
`hwp new` → `hwp_new`, `hwp fill` → `hwp_fill`, `hwp render` → `hwp_render`,
`hwp validate` → `hwp_validate`. 규정 린터 (`hwp_lint`)는 2.3 단계에서 도입됩니다.
서버는 항상 최소 하나의 `--root`를 지정해 시작해 도구가 샌드박스 작업 공간만 접근하게
하세요. 도구 상세, 샌드박스 의미, 클라이언트 설정은 SKILL.md의 MCP 절에 있습니다.

## 7. 한컴 오피스 최종 확인

자체 검증 (`hwp validate`, `hwp render`)은 회귀를 잡아내지만, 최종 판정은 **한컴
오피스가 파일을 여는가** — 손상, 변조, 복구 대화 상자 없이 — 그리고 보여주는 내용이
의도와 일치하는가입니다. 문서가 도구 고리를 벗어날 때는 출력을 한컴 오피스에서 열어
확인한 뒤 전달하세요.
